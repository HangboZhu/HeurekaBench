## 2. 根因

难度闭环为把题出难，持续要求模型"跨背景做定量比较、追加反事实追问"，而出题 prompt 只约束了
**形式**（自包含、题干长度、rubric 粒度、单一考点），**完全没有约束证据边界**——
没有任何一条规则禁止跨基线相减、用 P 值排通路、或从充分性实验断言唯一性。
9/10 被点名说明这是系统性缺陷而非偶发；4 道 block 里 3 道（下标 3、6、9）正是"为了更难
而新增的跨背景定量比较"。

## 3. 修复内容

### 3.1 系统性预防（防复发）

**a) 出题 prompt 新增 "Evidential validity" HARD REQUIREMENT**
（`benchmark_creation/prompts/insight2question_rubric_prompts.py`，MCQ/OE 两套模板都加）
把外审暴露的 8 类错误推断写成禁令，并要求每个定量前提可溯源：
跨基线/跨背景百分比运算、用 P 值排通路位置、比较不同统计量（F/t/R²/OR）、
从充分性断言必要性/唯一性/obligatory、把阴性结合实验当普遍排除、用组成比例反推单细胞产量、
混杂操作（载体/盒式/注射）不得归因、反事实只能在证据能识别方向时提问。

**b) 校验器新增启发式告警**（`benchmark_creation/validate_question_pack.py`）
新增 `evidential_warnings()`：跨背景百分比运算、`pp` 单位误用、跨背景"残余"计算、
P 值排序措辞、R² 与 F 混比、`obligatory/unique/唯一 gate` 类过强表述、
阴性结果普遍排除、per-cell 产量措辞、载体/共变因素提示。
实现上做了精度调优：减法算子必须紧贴第一个百分比（避免把"...−28.3% and...−35.2%"这种
并列观测误判为相加）；按句识别否定语境（"does NOT license ... obligatory"、"not per-cell
production"）则抑制告警。

**c) 纯 question 导出**（`benchmark_creation/export_eval_questions.py --questions-only`）
响应外审"确保模型只见 question，不见同文件的 answer/rubric"，新增
`<qtype>_questions_prompts.json`（仅 question，MCQ 另含 options）。本次已生成
`oe_questions_prompts.json`。

### 3.2 逐题修复

新增 `benchmark_creation/repair_reviewed_items.py`：把外审对每题的批评**逐条注入** prompt
（复用标准 rubric prompt，自带新的 Evidential validity 约束），要求"只保留证据能支持的结论，
或改成明确询问还需要什么测量"，逐题落盘、可断点续跑。输入为
`review_critiques.json`（9 条，内容为外审发现 + 具体缺陷）。

修法取向：4 道 block 撤销唯一答案，改为"证据能支持什么 / 还有什么不能识别 / 需要什么测量
才能判定"；5 道 fix 收紧过强表述。例如：

- 下标 6：新 F1 明确写"`+20.0%` 与 `−25.7%` 参照组不同、不能合成残余"，
  评分标准把"算出 −5.7%"直接判为 1 分答案
- 下标 9：删掉整条"P 值排序/反转"推理，改为"P 值能说明什么、不能说明什么"+
  "设计一个不含外源救援的实验来检验分支独立性"
- 下标 8：删除虚构分组，F5 明确写"'星形胶质细胞 FN1 特异性'未被该设计建立"

改动前已备份 `oe_questions_backup_prereview_repair.json` / `..._eval_backup_...`。
